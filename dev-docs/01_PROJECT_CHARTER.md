# 01 - Project Charter

## Audiences

### Primary
- Data Engineering hiring managers
- Senior Data Engineers / Analytics Engineers
- Technical recruiters

### Secondary
- General engineering managers
- Professional contacts
- Other developers reviewing GitHub

## Goals

- Demonstrate job-ready AWS data engineering capability.
- Demonstrate strong SQL and practical production Python.
- Demonstrate PySpark and distributed-processing competence.
- Prove architecture, security, observability, testing, and cost awareness.
- Provide a live but controlled demonstration.
- Serve as a permanent portfolio artifact even when expensive AWS resources are destroyed.

## Non-goals

- Operate a real retail business.
- Store real customer PII.
- Keep every AWS service running continuously.
- Use a service solely because it exists.
- Build a giant general-purpose SaaS application.
- Provide public AWS Console access.

## Portfolio principles

- Public-first: reviewers should see substantial value without creating an account.
- Evidence-first: screenshots alone are secondary to code, tests, metrics, lineage, and reproducible infrastructure.
- Least privilege: live-demo users never receive direct AWS credentials.
- Cost-aware: idle expensive infrastructure is stopped or destroyed.
- Deterministic data: historical datasets are reproducible by seed.
- Realistic imperfection: bad, duplicate, late, and evolving data are intentional.
- Progressive complexity: each phase builds on previous phases.
